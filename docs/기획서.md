# 운동 앱 기획서 (1차 버전)

> 이 문서는 Claude Code가 읽고 개발을 시작할 수 있도록 작성했다. 개발자는 비전공자이므로, 작업 전에 계획을 쉬운 말로 설명하고, 한 번에 한 단계씩 진행하며, 단계마다 실행해서 확인할 방법을 알려준다.

## 0. 기술 스택

- 앱: Flutter (아이폰 + 안드로이드)
- 서버/DB/로그인/파일: Supabase (Auth, Postgres, Storage, Edge Functions)
- AI: Claude API (Edge Function에서만 호출, 앱에서 직접 호출 금지)
- 푸시 알림: Firebase Cloud Messaging (FCM). 알림 전송은 Edge Function에서 처리
- 구독 결제: 앱스토어/구글 플레이 인앱 결제 (패키지는 개발 순서 10단계에서 선택)

## 1. 한 줄 정의와 대상

- 한 줄 정의: 내 몸 정보로 TDEE를 계산해 AI가 식단과 운동 루틴을 짜주고, 트레이너가 PT 회원님께 운동일지까지 챙겨주는 운동 앱
- 대상: 일반 사용자 + 앱 제작자(트레이너)에게 PT를 받는 회원님. 두 부류가 똑같이 중요함
- 차별점: TDEE 기반 AI 식단·루틴 + 현직 트레이너 연결(운동일지, PT 문의)
- 사용자 역할 3가지: `user`(일반), `member`(PT 회원), `trainer`(선생님, 앱 제작자 본인 1명)

## 2. 1차 버전 기능 범위

### 1차에 넣는 기능 (5개)

1. 몸 정보 입력 → 운동 강도 반영 TDEE 계산
2. AI 식단 생성 (일주일 / 한 달)
3. AI 운동 루틴 생성 (일주일 / 한 달)
4. 식단 올리기(사진 + 한 줄 설명) → AI 답변
5. PT 회원 운동일지 (선생님이 작성하고 운동 영상도 첨부, 회원님은 본인 것만 열람)

### 참여 기능 (1차에 함께 넣음, 자세한 내용은 14번)

1. 연속 기록(스트릭)과 쉬는 날 보호
2. 오늘의 작은 목표 3개 (운동 완료 체크 포함)
3. 소수의 배지
4. 선생님 응원 스탬프와 주간 미션
5. 연속 기록 알림

### 운동 종목 방식

- 흔한 종목 50~100개를 `exercises` 테이블에 미리 넣어둔다 (Claude Code가 목록을 만들어 넣을 것). 홈트용 종목 약 30개를 포함하고 장소·장비·충격·소음 태그를 함께 넣는다 (홈트 조건은 16번)
- AI 루틴은 이 목록의 종목만 사용한다 (AI에게 종목 id 목록을 주고, 그 안에서만 고르게 함)
- 목록에 없는 운동은 선생님이 일지를 쓸 때 직접 추가한다 (`custom_name`)

### 나중에 추가 예정 (1차에는 만들지 않음)

- 운동 용어·영상·사진 카테고리 (운동일지의 영상 첨부는 1차에 포함)
- 선생님이 직접 다는 식단 답변
- 회원님이 직접 쓰는 운동 기록
- 건강 앱 연동 (애플 건강, 헬스 커넥트)
- 이메일 로그인
- 광고, 일회 결제
- 경험치·레벨, PT 회원 팀 챌린지, 성과 그래프와 월간 요약

## 4. 디자인 방향

- 흰 배경 + 청록(초록 계열) 포인트의 깔끔한 밝은 스타일. 식단 기록 앱 느낌
- 포인트 색은 임시값이며 나중에 바꿀 수 있으므로, 색은 반드시 한 곳(테마 파일)에서만 정의한다
- 임시 색상: 포인트 `#0E9F8E`, 배경 `#FFFFFF`, 보조 배경 `#F4F7F6`, 글자 `#14211F`, 보조 글자 `#5B6B68`, 경고 `#D9534F`
- 글자가 많은 화면(식단표, 운동일지)은 읽기 편하게 여백을 넉넉히 둔다
- 다크 모드는 1차에서 만들지 않는다

## 5. 회원 / 비회원

- 비회원: S01~S04 (몸 정보 입력 → TDEE 결과)까지만. 서버 저장 없이 앱 안에서만 계산
- 회원: 소셜 로그인 (카카오 + 구글 + 애플). Supabase Auth 사용
- 가입 후 사용 가능: AI 식단·루틴 생성, 식단 올리기, 내 정보
- PT 회원: 초대 코드로 연결 후 운동일지 사용
- 로그인 직후 비회원 때 입력한 정보가 있으면 `profiles`에 저장하고 바로 S06으로 이동
- 아이폰 앱은 소셜 로그인을 제공하면 애플 로그인도 필요하므로 세 가지를 함께 넣는다
- 나중에 추가 예정: 이메일 로그인

## 6. 데이터 저장 방식

### 결정: Supabase

### 이유 (쉬운 말)

- 회원별 잠금 서랍이 달린 보관함과 같다. 운동일지를 본인만 보게 하는 규칙을 화면이 아니라 **데이터 보관함 자체**(RLS)에 건다. 누가 억지로 열어 봐도 남의 데이터는 나오지 않는다
- 카카오·구글·애플 로그인을 기본으로 지원한다
- AI 사용 열쇠(API 키)를 앱 안에 넣지 않고 서버(Edge Function)에 보관해서 키 탈취와 비용 폭탄을 막는다. 비회원 차단과 횟수 제한도 여기서 처리한다
- Flutter 자료가 많아 막혔을 때 해결하기 쉽다
- 대안(Firebase)은 카카오 로그인 연결과 "본인만 보기" 규칙 설정이 더 어려워 선택하지 않았다

### 테이블

### 보안 규칙(RLS) — 반드시 지킬 것

- 모든 테이블에 RLS를 켠다. 켜지 않은 테이블이 없는지 마지막에 점검한다
- `profiles`, `plans`, `meal_posts`: 본인 행만 읽기/쓰기
- `workout_logs`, `log_items`: 읽기는 `member_id = auth.uid()` 인 회원 본인만, 쓰기/수정은 `role = trainer` 인 선생님만
- `invite_codes`, `trainer_links`: 선생님만 코드 생성. 코드 입력(연결)은 Edge Function으로만 처리
- `role`을 앱에서 직접 바꾸지 못하게 한다. `trainer` 권한은 Supabase 관리 화면에서 개발자 계정에 직접 지정한다
- `exercises`: 로그인 사용자 모두 읽기 가능, 수정은 선생님만
- 식단 사진 저장소(Storage)는 비공개로 두고, 본인 폴더(`{user_id}/...`)만 접근 허용
- 운동일지 영상 저장소는 별도 비공개 버킷으로 두고, 경로는 `{member_id}/{log_id}/...`. 업로드는 해당 회원의 선생님만, 재생은 해당 회원 본인과 작성한 선생님만 가능하게 한다. 재생 주소는 짧은 유효시간의 임시 주소(signed URL)로 제공한다. 만료된 영상은 하루 한 번 도는 예약 작업(Edge Function)이 영상 파일과 `log_videos` 행을 함께 삭제한다

### Edge Function

- `generate-plan`: 몸 정보 + 강도 + 기간 → 식단·루틴 JSON 생성 후 `plans`에 저장
- `review-meal`: 올린 식단(사진 + 글) → 피드백 생성 후 `meal_posts.ai_reply` 저장
- `redeem-invite`: 초대 코드 확인 → `trainer_links` 생성, `profiles.role = member`, 코드 사용 처리
- `send-push`: 운동일지가 올라오면 해당 회원님께 알림. 하루 한 번 리마인더 예약 발송
- 모든 AI 함수는 로그인 확인 → 사용 횟수 확인 → AI 호출 → 횟수 +1 순서로 처리한다

### 계산 규칙

- BMR 기본: Mifflin-St Jeor 공식 (남: 10×체중 + 6.25×키 − 5×나이 + 5, 여: 10×체중 + 6.25×키 − 5×나이 − 161)
- BMR 체지방량 입력 시: Katch-McArdle 공식 = 370 + 21.6 × 제지방량 (제지방량 = 체중 − 체지방량). 체지방량이 '잘 모르겠음'이거나 비어 있거나 체중의 60% 이상이면 입력 오류로 보고 기본 공식을 쓴다
- 활동 계수(현재 강도): 하 1.375 / 중 1.55 / 상 1.725
- TDEE = BMR × 활동 계수
- 목표 칼로리: 감량 TDEE의 −15~20%, 유지 TDEE, 증량 +10~15%
- 안전 하한선(초안값, 출시 전 검토): 목표 칼로리가 여성 1,200kcal, 남성 1,500kcal 아래로 내려가지 않게 한다
- 근육량(선택, '잘 모르겠음' 가능)은 AI 프롬프트의 참고 정보로만 쓰고 TDEE 공식에는 직접 넣지 않는다 (골격근량은 제지방량과 다른 값이라 공식에 바로 쓰기 어렵다)
- 결과 화면에 어떤 공식으로 계산했는지 표시한다
- 원하는 강도는 루틴의 세트 수·빈도·무게 안내에 반영한다

### AI 생성 시 지킬 점

- AI는 정해진 JSON 형식으로만 답하게 하고, 앱에서 JSON을 검증한 뒤 저장한다 (형식이 틀리면 1회 재시도)
- 루틴은 `exercises` 목록의 id만 사용하게 한다
- 홈트 조건 필터: 운동 장소, 장비, 층간소음 걱정, 운동 시간에 맞는 종목만 쓴다. 소음 걱정이 '예'이면 `impact = high` 또는 `noise = loud` 종목을 제외한다. 장소가 집이면 사용자가 가진 장비의 종목만 쓴다. 운동 시간에 맞춰 종목 수와 세트를 조정한다 (초안: 15분 3종목, 30분 4~5종목, 45분 6~7종목)
- 통증 부위가 있으면 관련 종목을 제외한다. 운동 효과나 소모 칼로리를 단정하는 문구는 쓰지 않는다
- 식단의 모든 음식은 양을 g(그램)으로 적게 한다 (개수나 컵 같은 단위는 쓰지 않는다)
- 음식마다 영양이 비슷한 대체 음식을 g 수와 함께 만들게 한다. JSON은 음식 항목마다 `{food, grams, alt: {food, grams}}` 형태로 받는다
- 식약처 DB(D1)의 100g당 영양값에 g 수를 곱해 끼니 칼로리를 계산하고, 대체 음식의 칼로리가 원래 음식과 ±10% 이상 차이 나면 g 수를 조정하게 한다 (±10%는 초안 값)
- 화면에 "g 수와 칼로리는 AI가 추정한 값"이라는 안내를 표시한다. 한 끼 전체를 바꾸는 기능(E4)은 2차로 따로 둔다
- 화면 어딘가에 "의료 조언이 아닙니다" 문구를 표시한다
- 몸 정보와 식단 사진은 민감한 정보이므로 로그에 남기지 않는다

### 운동일지 영상

- 선생님이 일지를 쓸 때 영상을 촬영하거나 앨범에서 골라 올린다. 업로드 전에 기기에서 압축한다
- 한도: 일지당 최대 5개, 영상당 15초 이내. 촬영은 15초가 되면 자동 종료하고, 앨범에서 고른 영상이 15초보다 길면 앞 15초만 올린다 (앱에서 자르고 압축한 뒤 업로드)
- 영상에는 회원님 얼굴이 담기므로 촬영·저장 동의를 받는다 (13번 법적 체크리스트)
- 일지를 삭제하거나 회원이 탈퇴하면 영상도 함께 지운다
- 저장 방식(확정): 서버에는 임시로만 보관한다. 선생님이 올리면 `expires_at`(초안 값: 올린 날부터 30일)을 정하고, 회원님이 일지 상세에서 [내 폰에 저장]을 누르면 회원님 폰(갤러리 또는 앱 저장소)에 저장한다. 저장해도 서버 사본은 만료일까지 유지하고, 만료되면 자동 삭제한다
- 만료 7일 전에 "영상이 곧 삭제돼요. 폰에 저장해 주세요" 알림을 보낸다. 만료 후에는 일지 글은 남고 영상만 사라졌다고 안내한다
- 회원님의 개인 클라우드(구글 드라이브, 아이클라우드)에 선생님이 직접 넣는 방식은 쓰지 않는다 (회원님 기기에서 회원님이 승인해야만 가능하고, 아이폰·안드로이드 방식이 달라 개발이 두 배가 된다)
- 비용 참고: 15초 영상 약 5MB(추정), 회원 30명 기준 월 약 4GB씩 증가. Supabase Pro는 파일 저장 100GB와 다운로드 250GB가 포함되고 초과분은 저장 GB당 약 $0.021, 다운로드 GB당 $0.09 (출시 전 최신 요금 확인). 영상 비용은 AI 비용과 별도다

## 7. 유료화

- 방식: 구독 (월 / 연). 1차에서는 구독 하나만 제공
- 무료/유료 경계: 사용 횟수
  - 무료: 가입 후 식단·루틴 생성과 AI 식단 답변을 월 N회까지
  - 유료: 횟수 확대 또는 무제한
  - N 값은 출시 직전에 AI 비용을 보고 정한다. 코드에서는 한 설정 파일의 상수로 관리한다
- 스트릭 프리즈: 무료 회원 월 1~2회(초안: 월 1회), 유료 회원은 더 많이 (횟수는 출시 직전에 정한다)
- 운동일지는 PT 회원 전용이며 앱 결제와 별개다. 일반 사용자는 S12에서 예시 화면과 [PT 문의하기]로 안내한다
- 인앱 결제 수수료가 붙으므로 가격은 수수료를 감안해 정한다
- 나중에 추가 예정: 광고, 일회 결제

## 8. 폰 기능과 플랫폼

- 플랫폼: 아이폰 + 안드로이드 동시 지원
- 푸시 알림
  - 선생님이 운동일지를 올리면 해당 회원님께 알림
  - 사용자가 정한 시간에 하루 한 번 "오늘 식단과 운동을 확인하세요" 리마인더
  - 알림 시간과 켜고 끄기는 '내 정보'에서 설정, 알림 권한은 처음 필요할 때 요청
  - 기록이 끊길 것 같은 저녁에 하루 한 번 알림 (오늘 목표를 아직 못 채웠을 때만, 주당 횟수 상한은 초안 값 주 3회, 쉬기 모드 중에는 보내지 않음)
  - 일지 영상 만료 7일 전 알림
  - 광고성이 아닌 서비스 알림으로 설계하고, 문구는 법적 체크리스트 L8과 함께 검토한다
- 건강 앱 연동(애플 건강, 헬스 커넥트): 나중에 추가 예정. 1차에서는 만들지 않는다

## 9. 출시 전 챙길 것

- AI 식단 안전장치 (하한선, 의료 조언 아님 문구)

## 10. 확정된 무료 데이터 활용

- D1 식약처 식품영양성분 DB (1차): 식단 올리기에서 음식 이름 검색, 칼로리·탄단지 자동 입력, AI 식단의 영양값 근거. 공공데이터포털 개발 계정은 트래픽 10,000건이므로 출시 전에 활용사례를 등록해 증설을 신청한다

- 외부 데이터마다 이용 조건과 출처 표시 의무를 확인하고 앱에 반영한다

## 13. 법적 준비 체크리스트

법률 조언이 아니다. 5단계(DB 설계) 전에 개인정보 전문가에게 상담하고, 출시 전에 처리방침·동의서를 검토받는다.

- L1 건강정보는 민감정보: 일반 개인정보 동의와 분리해 별도 동의. 목적, 항목, 보유 기간, 거부권 고지. 운동일지 영상 촬영·저장 동의 포함
- L2 만 14세 미만 가입 차단: 가입 화면에서 만 14세 이상 확인, 나이 입력이 14세 미만이면 차단. 만 19세 미만에게는 감량 목표 제한 검토
- L3 개인정보처리방침 공개: 앱 안과 스토어 페이지 모두
- L4 AI 국외 처리위탁·이전 고지: 수탁자(AI 사업자), 이전 항목, 이전 국가, 목적을 처리방침에 기재. AI에는 이름·이메일 없이 필요한 최소 정보만 전송. 사진·영상에 얼굴이 나오지 않게 안내
- L5 인공지능기본법: 가입 화면·약관에 AI 기반 서비스 고지, 식단·루틴·AI 답변 화면에 AI 생성 표시
- L6 의료기기·의료행위 경계: 질환자 대상 식단 처방이나 치료·개선 효과 표현 금지, "의료 조언이 아닙니다" 문구, 질환이 있으면 의사 상담 안내
- L7 선택 권한 거부로 서비스를 막지 않음: 알림 권한을 거부해도 앱 사용 가능, 카메라·사진은 해당 기능에서만 요청
- L8 광고성 푸시는 별도 수신 동의, 야간 광고는 별도 동의
- L10 선생님 계정 보안: 강한 인증, 접근 기록, 회원 정보를 개인 메신저로 주고받지 않기
- 보류(전문가 상담 뒤 확정): L9 보호책임자·안전 조치, L11 회원 기록의 홍보 사용 동의, L12 사업자등록·통신판매 신고 여부

## 14. 확정된 참여 기능 (게임 요소)

원칙: 보상은 기록하기, 운동 완료 같은 **행동**에만 준다. 체중 감량 속도나 적게 먹은 칼로리에는 보상하지 않는다.

### 1차

- **연속 기록(스트릭)**: 하루의 기준은 사용자 기기 시간대의 자정(초안). 그날 식단 올리기 또는 오늘 운동 완료 중 하나만 해도 이어진다. 루틴상 휴식일은 자동으로 인정한다
- **쉬기 모드**: 아프거나 다쳤을 때 사용자가 켜면 연속 기록이 유지되고 알림이 멈춘다. 최대 기간은 초안 값 7일
- **스트릭 프리즈**: 하루를 놓쳐도 연속 기록을 지켜 준다. 무료 월 1~2회(초안: 월 1회), 유료 회원은 더 많이. 매월 초에 횟수를 채운다
- **오늘의 작은 목표 3개**: 식단 1끼 올리기 / 오늘 운동 완료 체크 / 이번 주 몸무게 기록(주 1회). 홈 화면에 표시한다
- **운동 완료 체크**: 운동 화면에서 종목별로 체크하고 [오늘 운동 완료]를 누른다. 연속 기록, 목표, 배지가 모두 이 체크를 기준으로 움직인다
- **배지**: 첫 식단, 7일 연속, 첫 PT 일지 확인, 한 달 운동 20회 (1차는 이 4개만)
- **선생님 응원과 주간 미션**: 선생님이 회원별 이번 주 미션을 입력하고(S18) 일지에 응원 스탬프를 남긴다(S19). 일지를 저장하면 그날 출석 도장이 자동으로 찍힌다. 회원님 홈에 이번 주 미션이 표시된다
- **연속 기록 알림**: 8번(폰 기능)의 규칙을 따른다

### 2차

- 경험치와 레벨
- PT 회원 팀 챌린지 (협동형 합계 목표, 닉네임으로 표시, 참여는 선택)
- 성과 그래프와 월간 요약 (보류했던 주간 리포트 E3와 연결)

### 하지 않는 것

- 체중·칼로리 기준 순위와 보상 (과도한 다이어트와 섭식장애 위험)
- 개인 순위 리더보드 (건강정보 노출 위험)
- 기록이 끊겼을 때 죄책감을 주는 알림 문구
- 현금·경품 보상 (법과 세금 문제)

### 개발할 때 챙길 점

- 연속 기록 계산은 서버에서 하루 한 번 정산하고 앱은 보여주기만 한다 (기기 시간 조작 방지)
- 같은 날 중복 기록은 한 번으로 센다
- AI 비용은 거의 늘지 않는다 (앱 안의 규칙으로 처리)

## 15. 확정된 통계

화면: S20을 "내 기록"으로 확장해 위쪽에서 [연속 기록 | 통계]를 전환한다. 새 탭은 만들지 않는다.

### 1차

- **T1 운동 달력**: 이번 달에 운동한 날과 쉬는 날(루틴의 휴식일, 쉬기 모드 기간)을 달력에 표시한다. 데이터는 `activity_days`
- **T2 이번 주 운동 완료율**: "이번 주 루틴 4일 중 1일 완료"처럼 표시한다. 분모는 `plans`의 운동일 수이고, 휴식일과 쉬기 모드 기간은 뺀다. 완료는 `activity_days.workout_done`

### 2차

- **T3 체중 변화 그래프**: 7일 평균선을 함께 보여주고, 그래프를 숨기는 옵션을 둔다. 몸무게 재입력(B4)과 연결한다
- **T4 종목별 기록 추이** (PT 회원): `log_items`의 `exercise_id` 기준으로 집계한다. 선생님이 직접 추가한 종목은 이름이 같을 때만 묶는다
- **T5 식단 통계**: 주간 평균 칼로리와 목표 비교, 탄단지 비율. "기록된 식단 기준"이라고 표시한다
- **T6 월간 요약 카드**: 운동 횟수, 최장 연속 기록, 배지. AI 요약 문장은 Haiku로 건당 약 ₩1이며 주간 리포트(E3)와 연결한다

### 보류

- T7 선생님용 회원 현황, T8 총 운동량

### 공통 원칙

- 횟수, 완료율, 추이처럼 행동 중심으로 보여주고, 다른 사람과의 비교나 순위는 넣지 않는다
- 기록이 7일 미만이면 그래프 대신 "기록이 쌓이면 보여드려요"라고 안내한다 (초안 값)
- 통계는 본인 것만 보이고, 선생님은 PT 회원 데이터만 본다 (기존 RLS 규칙)
- 집계는 서버(DB 함수나 뷰)에서 계산하고 앱은 보여주기만 한다. 차트는 Flutter 차트 패키지(예: fl_chart)를 쓰되 사용 전에 최신 상태와 라이선스를 확인한다
- AI 비용은 T6의 요약 문장을 빼면 들지 않는다

## 16. 확정된 홈트레이닝

### 1차

- **홈트 조건 입력**: 운동 장소(헬스장/집/둘 다), 집에 있는 장비(맨몸/밴드·덤벨), 층간소음 걱정(예/아니오), 한 번에 운동할 시간(15/30/45분). S03에서 받고 내 정보에서 수정할 수 있다
- **종목 태그**: `exercises`에 place, equipment, impact, noise, 쉬운/어려운 변형 연결을 넣는다
- **AI 홈트 루틴**: 조건에 맞는 종목만 골라 루틴을 만든다. 별도 프로그램 메뉴는 없다. 규칙은 6번 "AI 생성 시 지킬 점"
- 운동 화면 상단에 현재 운동 조건을 표시한다. 장소가 '둘 다'이면 헬스장 날과 집 날을 섞어서 짠다
- 참고 기준: WHO 성인 기준은 주 150~300분의 중강도 운동(또는 75~150분의 고강도 운동)과 주 2일 이상의 근력 운동이다. 홈트 루틴도 주 2~3일 근력을 기본으로 한다

### 2차

- **고정 프로그램 메뉴 5종** (수치는 초안 값)
  - P1 집에서 시작하기: 맨몸 전신, 주 3회, 20~25분
  - P2 조용한 홈트: 점프 없는 저충격, 주 3~4회, 20~30분
  - P3 밴드·덤벨 근력: 상·하체 분할, 주 3~4회, 40분
  - P4 10분 짧게: 바쁜 날과 쉬기 모드 후 복귀용, 10분
  - P5 홈 서킷: 저충격 유산소 + 근력, 주 4회, 30분. 소모 칼로리 효과는 단정하지 않는다
- **자동 난이도 올리기**: 목표 갯수를 채우면 갯수나 무게를 올리고, 쉬운 동작에서 다음 단계 변형으로 넘어간다
- **선생님 시연 영상과 PT 회원 홈트 숙제**: 선생님이 시연 영상을 찍어 종목에 붙이고, "이번 주 홈트 2회"를 주간 미션으로 준다

### 보류

- 걷기 목표 안내: 걸음 수 자동 기록은 건강 앱 연동과 함께 검토한다

### 안전 규칙

- 소음 모드가 켜져 있으면 점프, 버피, 마운틴 클라이머 같은 소음이 큰 종목은 AI가 쓰지 못한다
- 통증 부위와 관련된 종목은 제외한다 (예: 무릎 통증이면 점프와 깊은 스쿼트, 허리 통증이면 슈퍼맨)
- 질환이 있는 사용자는 의사 상담을 안내한다 (13번 L6)
- 자세가 중요한 종목은 시연 영상이 필요하다 (선생님 시연 영상 또는 D4)

## 17. 개발 순서

1. 프로젝트 세팅: Flutter 프로젝트, Supabase 프로젝트, 폴더 구조, 테마 파일(색과 글꼴을 한 곳에서 관리)
2. 화면 뼈대: 하단 탭 5개와 S01~S20을 더미 데이터로 만들고 화면 이동 확인
3. 비회원 흐름: S01~S04와 TDEE 계산 함수(체지방량 있으면 Katch-McArdle, 없으면 Mifflin-St Jeor). 계산은 테스트 코드로 검증
4. 소셜 로그인과 `profiles`: 카카오·구글·애플 로그인, 만 14세 이상 확인, 건강정보 별도 동의 화면
5. DB와 보안: 모든 테이블(영상, 연속 기록, 배지, 미션, 일지 종목 기록 `log_items` 포함), RLS 규칙, 식단 사진·일지 영상 저장소, 종목 목록 입력(D6 + 한국어화 E5, 홈트용 약 30종과 태그 포함). 이 단계 전에 개인정보 전문가 상담
6. AI 식단·루틴 생성: `generate-plan`, 입력 항목 보강(B1, 홈트 조건 필터 포함), D3 검증, 안전 하한선, AI 표시, 실패 안내와 다시 시도(B6), S06~S07, S11
7. 식단 올리기: 사진 업로드, D1 연동, E1(사진 분석 + DB 영양값), 오늘 먹은 칼로리 누적(B2), S08~S10
8. 운동 완료 체크와 참여 기능: 종목 체크, [오늘 운동 완료], 연속 기록 정산, 쉬기 모드, 프리즈, 오늘의 목표 3개, 배지 4개, S20 내 기록(연속 기록 + 통계 T1·T2)
9. PT 기능: 초대 코드(유효 7일, 연결 해제), 선생님 화면(회원 관리, 주간 미션, 응원 스탬프, 출석 도장), 운동일지(무게 → 횟수 → 세트), 영상 촬영·업로드·재생, 임시 보관과 [내 폰에 저장], 만료 자동 삭제, RLS 점검
10. 푸시 알림: FCM 연동, `send-push`, 일지 도착, 하루 한 번 리마인더, 연속 기록 알림, 영상 만료 알림, 알림 설정
11. 사용 횟수 제한과 구독: `ai_usage` 확인 로직, 인앱 결제, 구매 복원, 해지 안내, 프리즈 횟수 차등
12. (1차 후반) 일지 초안 도우미(E2)
13. 마무리: 계정 삭제, 처리방침·약관·동의서(국외 위탁과 AI 사용 고지, 영상 보관 기간), 오류·이용 분석 도구(B10), 스토어 등록 자료(B9), RLS 최종 점검
14. 테스트와 출시: 아이폰·안드로이드 실기기 테스트, 스토어 등록과 제출
